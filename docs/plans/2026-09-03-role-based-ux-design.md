# 方辑双角色用户体验设计

> **已被取代（2026-10-05）。** 可核对的界面约定以 [docs/DESIGN.md](../DESIGN.md) 为准。下文保留作当时的设计记录，文末的核销表只说明哪些句子已经落到代码里。

## 目标与边界

本次优化聚焦方言材料校对员和项目管理员的高频工作，不改变双人盲校、管理员仲裁、PDF/CSV 导入等后端协议。设计方向是“档案校勘工作台”：用纸张、墨色和朱砂批注的视觉语义承载专业资料处理，同时保持界面克制、紧凑、清晰。校对员只需判断“我现在该处理哪个项目、内容是否安全保存、提交会发生什么”，界面不显示一校或二校，避免轮次预期干扰独立判断；管理员需要尽快判断“哪个项目需要介入、问题集中在哪个状态、批量操作影响哪些条目、仲裁是否逐项确认”。成功标准是关键动作在首屏可见、状态无需依靠颜色辨认、不可逆操作有明确确认、窄屏与键盘操作可用，并保留现有服务接口与数据完整性约束。

## 校对员工作流

项目大厅从横向数据表改为响应式项目工作卡。页面顶部汇总“进行中的项目、可领取项目、已完成条目”，每张卡只展示项目名、描述、完成进度、可领取数量和个人进行中。首要按钮只表达继续或领取任务，不提示后台校对轮次。编辑器保留 PDF 与结构化字段的左右对照，右侧使用纵向字段卡，始终显示原始值、编辑值、当前字段和修改字段数；每个字段都能恢复原文。顶栏显示项目、条号、当前任务位置与草稿状态。提交动作先进入摘要确认，明确本次修改字段数以及提交后的自动流转，再执行不可撤销的校对提交。字符板保留光标插入行为，并使用可折叠分组降低长页面占用。加载、无 PDF、草稿恢复、提交失败及任务被他人领取等状态继续在当前页面反馈。

## 管理员工作流

控制台从“总量展示”升级为异常优先的运营总览：统计总项目、总体完成率、处理中条目和待仲裁条目；项目列表显示内部校对阶段、仲裁与完成分布，并把需要仲裁的项目置于更明显的位置，提供直达待仲裁筛选的按钮。项目详情顶部提供可点击状态概览和页内导航，让管理员在“文件准备、导出、条目管理”之间快速移动；来自控制台的状态查询会直接应用到条目筛选。现有搜索、分页和批量排序/删除保持不变，但选择范围、当前筛选结果和危险操作反馈更醒目。仲裁复用校对编辑器的 PDF 双栏工作区，默认聚焦不一致字段并动态渲染全部校对结果，支持采用原文、任一结果或手工编辑；所有差异字段必须明确确认或编辑后才能提交。匹配字段仍可展开检查，最终提交前显示确认摘要。

## 状态、可访问性与验证

界面使用文本、数字和图形共同表达状态，颜色只作为辅助。所有按钮具有可见焦点、忙碌状态与禁用原因；动态成功/错误信息使用合适的 `role=status` 或 `role=alert`；可点击卡片不会替代语义化按钮和链接。桌面端维持高效率双栏，1100px 以下自动改为单栏，管理表格在小屏保留水平滚动而不截断操作。纯函数负责状态汇总、任务动作和仲裁差异判断，并由 Node 单元测试覆盖；Vue 模板通过生产构建验证。视觉检查覆盖项目大厅、校对编辑器、管理员控制台、项目详情和仲裁页的正常、空、错误或禁用状态。该方案不增加数据库迁移，不改变权限模型，回滚只需恢复前端文件。
