# 模型辅助（L2）接入决策门

> 本文件是 **#181** 的交付物：**一份决策文档，不交付代码**。
> 非目标同样明确：不选型、不写 POC、不引依赖、不改 compose、不承诺任何上线时间或准确率。
>
> 结论提前给：**本轮不开任何 L2 实现 issue**，但阻塞点不是"技术上做不到"，
> 而是两条治理前提没落地（出境授权、可接受的首版准确率）。本文件把这两条变成
> 可提交、可回答的具体问题，并给出触发重开的条件。
>
> 与 **#122**（识别运行时的落地形态与部署/合规不变式）**共用一份部署决策**，
> 见 §2 末的对照表——OCR(L1) 与模型辅助(L2) 在部署形态上的约束高度重合，
> 各写一份必然漂移，也就会造成两次 compose 改动。

## 0. 现状证据（逐条核过，不是转述）

| 约束 | 出处 | 实测内容 |
| --- | --- | --- |
| 后端是静态二进制 | `backend/Dockerfile:1,26,30,48` | `golang:1.27-alpine` 构建、`CGO_ENABLED=0 go build -trimpath`、运行镜像 `alpine:3.24`、`USER 10001:10001` |
| 容器不可写、无能力 | `docker-compose.yml:10,31,32` | `read_only: true`、`cap_drop: [ALL]`、`security_opt: ["no-new-privileges:true"]`（前端 `:58-59` 同样两条） |
| 浏览器侧 CSP | `frontend/nginx.conf:16` | `default-src 'self'`、`script-src 'self'`、**`connect-src 'self' blob: https: wss:`**、`worker-src 'self' blob:`、`img-src 'self' data: blob:` |
| 许可 | `LICENSING.md`、`ASSET_BOUNDARIES.md`（**在仓库根目录，不在 `docs/`**） | 代码 `AGPL-3.0-only`；第三方资产按路径逐个登记 |
| 治理前提未决 | #92（资料来源与授权边界）、#97、#120 | 三个 issue 至今都是 OPEN |

### 一处必须纠正的常见误解

`#181` 正文把 CSP 侧的证据写成「`script-src 'self'` 禁 CDN，浏览器内推理需自带资产」——
这半句对，但容易读成"CSP 挡住了对外请求"。**挡住出站的是 `connect-src`，而它当前包含 `https:`**
（这是实时功能需要的，例如前端直连 PocketBase 之外的 https 端点）。
所以：

- **浏览器内推理在 CSP 上本来就是通的**（`worker-src 'self' blob:` 也已允许 worker + WASM/ONNX）；
- 反过来说，**CSP 不是出境的防线**。任何"默认不出境"的承诺都必须由配置与代码路径保证，
  不能靠 CSP 兜底——这直接影响 §4 的写法。

## 1. 四种形态：结论 / 代价 / 未决项

### 1.1 云 API（第三方推理服务）

- **结论**：技术上最省事，**但今天不能选**——它把"语料出境"这个未决问题从文档变成事实，
  而 #92 的授权边界还没落地。
- **代价**：每条推理请求携带原文片段（记音列与释义都是语料本体）；需要服务商的留存与
  训练用途书面条款；需要新的密钥管理（不入仓、不入镜像，见 #122 不变式 3）；
  延迟与成本随校对量线性增长；失败路径要么阻塞要么静默降级。
- **未决项**：① #92 是否允许把未公开语料发送给第三方；② 可接受的首版准确率（#120 点名）；
  ③ 谁为服务商条款签字（维护者无权定，见 §6）。

### 1.2 自托管 sidecar 容器

- **结论**：**与 #122 的决策是同一件事**，不该在本文件里单独定。
  #122 的不变式 1/3/4/5/6/7/8 全部适用，本 issue 不重复一套。
- **代价**：compose 增加服务与内网密钥；模型权重以只读卷提供；`read_only` 与推理运行时的
  临时写盘需求可能冲突（需要显式挂 tmpfs 并给预算）；镜像体积与内存/GPU 需求要实测；
  对外 router 不得新增端口。
- **未决项**：运行时形态未定（Python 进程？ONNX Runtime？编进 Go 静态二进制？）——
  这属于 #122 的自选范围，本文件不替它决定。

### 1.3 浏览器内推理（WASM / ONNX）

> 本节与 #120 附录的第 9 条是同一条路径，**不重做调研**：#120 已记录 PP-OCR 可在单个 HTML 内跑、
> 模型约 6 MB，Tesseract.js 支持多 worker，并指出约束是单页耗时与内存上限、
> 适合"当场跑几十页并预览"而不适合整本后台批处理。下面只补 #181 特有的两件事：
> 许可与 CSP 的真实作用域。

- **结论**：**这是唯一不需要出境决策的形态**，因为它从根上不产生跨域数据出口——
  推理在用户自己的浏览器里，原文不经过任何第三方。如果 §6 的出境问题长期悬而未决，
  这条路是唯一能先动的。
- **代价**：模型权重要入仓或以受控方式分发，逐个走 `ASSET_BOUNDARIES.md` 的路径登记并评估
  与 `AGPL-3.0-only` 的边界（模型许可证与代码许可证通常不兼容，这是最可能卡住的一点）；
  志愿者设备差异大（手机/低配机器），首字延迟和内存要实测；模型可被从浏览器里提取，
  对"权重许可"的要求因此更高，不是更低。
- **未决项**：① 候选模型的许可证是否允许再分发；② 低端设备上的可接受延迟；
  ③ 与 `#161` 的渲染预算冲突（同一页里既跑推理又做联动定位）。

### 1.4 不做（承认 L0/L1 已覆盖主要人力黑洞）

- **结论**：**这是本轮的选择**，而且它不是消极选项——L0 规则(#177) + 分列(#125) +
  缺字登记(#123/#205) 加起来的收益还没被量过，在没量过之前引入 L2 会让归因失效
  （见 §5 与 BII 的自反论证）。
- **代价**：一些只有语义近似/手写识别能解的问题继续靠人工（扫描页识读、同义写法归一）。
- **未决项**：无。本节本身就是决策。

## 2. 与 #122 共用的部署决策（避免两次改 compose）

同一张表，两个 issue 共用。**任何一行要改，#122 和 #181 必须一起改；只改一处即视为口径漂移。**

| 部署决策 | #122（OCR / L1） | #181（模型辅助 / L2） | 是否共用同一份改动 |
| --- | --- | --- | --- |
| `read_only` / 非 root / `cap_drop` / `no-new-privileges` 不放宽 | 不变式 1 | 同样适用 | ✅ 一次决定，两处引用 |
| 是否允许任何数据离开服务器 | 不变式 2 | §4 + §6 的核心问题 | ✅ 同一个决策，同一份记录 |
| 新增服务端口一律不进对外 router，内网密钥不入仓不入镜像 | 不变式 3 | 同 | ✅ |
| 模型权重的只读卷与缓存预算/TTL | 不变式 4 | 同（`backend/pdf_cache.go` 是同类先例） | ✅ |
| 运行时不可用不得拖垮登录/导入/校对/仲裁/导出 | 不变式 5 | 同，且见 §4「失败不得静默降级成没有疑点」 | ✅ |
| 资产许可逐路径登记 + `THIRD_PARTY_NOTICES.md` + AGPL 边界 | 不变式 6 | 同，且 L2 的权重许可更严（1.3） | ✅ |
| 结构化事件与 `X-Request-ID` 贯通 | 不变式 7 | 同 | ✅ |
| 吞吐与成本要有实测数字 | 不变式 8 | 同 | ✅ |

**推论：如果最终两个能力都要落地，compose 只应该改一次。**
先落地的那个 issue 负责改，后落地的引用同一份配置；顺序由谁先通过决策门决定，不由本文件指定。

- **结论**：部署形态是**一个决策两次引用**，不是两个决策。
- **代价**：共用意味着先落地的一方要为另一方预留（例如只读卷的挂载点命名）；
  如果两边同时开工，这张表就是唯一的仲裁依据。
- **未决项**：谁先落地未定；表内任何一行要改，两个 issue 必须同 PR 改，否则视为漂移。

## 3. `FindingProducer` 边界

目的：让 1.1 / 1.2 / 1.3 的形态更换**不改 #176 的数据结构**。签名已同步写入
[`2026-09-25-review-findings.md`](./2026-09-25-review-findings.md) §8，两处必须一起改。

```
FindingProducer = interface {
  // 输入：一个条目（页资产由实现按需自取），加上 producer 自己要读的上下文
  Produce(ctx ProducerContext) -> []FindingDraft

  // 元数据：写进 review_findings 的 producer / producer_version
  Identity() -> {producer: "rule"|"ocr"|"bundle_import"|"model",   // ← "model" 需 #176 加枚举值
                 version: string}
  // 能力声明：用于 §4 的隔离与 §5 的评测准入
  Capabilities() -> {needsEgress: bool, readsOtherPeopleSubmissions: false, writesBack: false}
}

FindingDraft = {
  page_id, field_name?, kind, severity ∈ {info|warn|strong},
  message_key, params_json,      // 只允许结构信息（码位/计数/列名/偏移）
  evidence_json,                 // {bbox?, char_offsets?, anchor} —— 见下方约束 4
  produced_at
}

ProducerContext = {
  page, project, column_roles, enabled_keyboards,   // 全部来自已有数据
  // 明确不存在的东西：他人的 attempt 内容、轮次线索、其他校对者的身份
}
```

三个约束必须由**接口字段**而不是文档措辞来保证：

1. `Capabilities().readsOtherPeopleSubmissions` 类型上是 `false` 字面量——生产者拿不到
   这个输入，所以"永不含他人提交"不是纪律而是不可表示（#175 红线 1）。
2. `needsEgress` 必须在注册时声明，供 §4 的出站闸门判断；未声明视为 `true`（保守）。
3. 生产者只返回 `FindingDraft`，**没有写回任何值的方法**（#177/#178 的非目标之一）。
4. **`params_json` 与 `evidence_json` 里不许出现原样内容片段**（#175 红线 1）。
   这两列都会随 hint 一起下发给该条目的在手校对员，早期草稿里那个 `evidence.excerpt`
   已经删掉——留着它等于在契约里给原文片段开一扇门。
5. **每条 finding 都必须自己决定挂在哪个条目上并声明口径**：`review_findings.page` 是
   必填关系字段（#176），所以"整列""整页""整项目"级别的疑点也必须挂某一条条目。
   挂靠规则由**生产者**决定、写进 `evidence.anchor`，写入端只认它、不许退化成
   "挂到第一条"——#208 的评审阻断 1 就是这个退化形状，后果是别人条目的内容
   发给了这一条的在手校对员。现成口径见
   [`2026-09-25-assist-rules.md`](./2026-09-25-assist-rules.md) §3.6（格级各归各条目 /
   列级挂扫描顺序第一条 / 页级挂该 PDF 页第一个条目 / 解析不出就跳过并计数）。
   模型生产者将来一定遇到同一个问题（一条"整页可疑"的输出挂哪），所以这里先写进契约。

**代价与未决项**：`producer` 枚举要加 `"model"`，这是一次 `assist_rule_gates`/
`review_findings` 的 select 值变更（迁移），本文件不擅自做，只标出它是唯一的 schema 影响点。
除它之外不需要改任何字段。

## 4. egress 不变式

| 条目 | 要求 | 为什么这样定 |
| --- | --- | --- |
| 默认关闭 | 未显式配置即完全不启用（`backend/main.go` 按环境变量注册外部服务是既有先例） | 少一条报错分支，也少一个"忘了关"的状态 |
| 出站白名单 | 允许的目的主机是**配置项且默认空**；未登记主机一律拒绝，不"记个日志再放行" | CSP 的 `connect-src` 含 `https:`，挡不住（§0） |
| 禁止正文外发 | 只有显式标注为可外发的字段能进请求体；默认全拒 | 语料授权未决（#92），宁可功能不工作 |
| 失败不得静默降级 | 生产者失败必须让 finding 批次标记为"未完成"，**不得表现为"该条没有疑点"** | 这是最危险的一类假阴性：界面干净了，其实是没跑成 |
| 密钥 | 不入仓、不入镜像、不进日志 | #122 不变式 3 |

- **结论**：出境控制的落点是配置与代码路径，不是 CSP。
- **代价**：默认关闭意味着"配好才能用"，多一次部署步骤；白名单为空时 L2 功能完全不启动。
- **未决项**：白名单由谁维护、审计记录留在哪（当前仓库没有集中日志设施）；
  "未完成批次"这个标记在 `review_findings` 上没有现成字段（可能要用一条 `info` 级 finding 表达，
  或在 `import_jobs` 侧记录），属实现期决定。

## 5. 数据隔离与评测要求

**隔离**：模型输入永不含其他校对者的提交（#175 红线 1）。落法不是"提醒实现者注意"，
而是 §3 的 `ProducerContext` 里根本没有那个字段。任何"为了准确率想读别人的结果"
的需求都要走 Steering 重新裁决，不在本决策门内。

**评测**：任何 L2 生产者上线前必须先过 #179 的尺子与门槛文件的判据：
按规则身份 `(producer, producer_version, kind, message_key)` 打分，
`strong` 要 `p̂ ≥ 0.90 且 n ≥ 100`、`warn` 要 `p̂ ≥ 0.60 且 n ≥ 150`，
达不到就停在 `off`。三条与 L2 特别相关的提醒：

1. **样本量门槛会先卡住 L2**。#179 实测：当前所有规则命中的是**个位数**，离 100/150 很远。
   引入一个模型生产者不会让这件事变容易，只会让它更难解释。
2. **精度只能在规则作用域内算**（recall 无定义，见 #179 结论）。所以"模型比规则强"
   这句话今天**没有可比的度量**，只有 precision 可比。
3. **BII（盲独立性）一旦破坏就无法回头**：把模型输出接进校对端会改变人工行为，
   人工行为改变会让"人工 vs 人工"的弱标注源枯竭——而那是唯一的尺子。
   因此 L2 若上线，必须先在**不回显给校对员**的模式下积累一批精度数字（管理端统计），
   再谈进校对端。这条是本文件对 #179 标注集可持续性的直接承诺。

- **结论**：评测准入沿用 #179 的尺子与 #206 的门槛，L2 不另立标准。
- **代价**：L2 在生产者注册后要先以"影子模式"跑一段（只写库不给校对端），这段时间的收益为零。
- **未决项**：影子模式要跑多久、多少样本算够，取决于试点进度，本文件不定数字
  （定了也没有数据支撑，那正是 #206 反对的做法）。

## 6. 必须提交 Steering 的事项

以下都不在本 issue 或维护者的决定权内（依 #92 / #97）：

1. **语料能否出境**：谁能签字、需要什么材料——见下节。
2. **训练用途**：原媒体授权不得推定为模型训练授权（#92 明写）。任何"用我们的语料微调"
   的提案都要单独过一遍授权，且与 §1.3 的"权重许可"是两个不同问题。
3. **对外准确率承诺**（#97）：本文所有数字都是相对于单一仲裁者的，不构成绝对准确率。
4. 第三方转移与服务商条款（§1.1）。

### 「语料能否出境」的结论与阻塞点

**结论：本决策门不能回答它，也不该假装回答。**它是一个授权问题，不是工程问题。
要回答，需要以下三样材料，缺一即维持"默认不出境"：

| 需要的材料 | 谁来提供 | 现状 |
| --- | --- | --- |
| 语料授权链条上「可否将原文发送给第三方推理服务」的书面许可 | #92 的责任方 + Steering | #92 仍 OPEN |
| 候选服务商的留存政策与「不用于训练」条款 | 采购/法务侧 | 未启动（本文件不选型，故无候选） |
| 可接受的首版准确率（决定 L2 是否值得引入） | #120 点名的未决前提 | 未定 |

**在三项到位之前，任何 L2 实现 PR 都应在评审阶段被以"缺授权"为由退回**，
而不是等代码写完再讨论。

## 7. 触发重开的条件

本轮结论是「不做」。满足以下任一条，就重开本决策门（而不是直接写代码）：

1. **#179 的尺子跑出真实数字**：出现至少一条规则 `n ≥ 100` 且完成一次升档评审——
   说明我们有能力判断"加一个模型生产者到底有没有变好"。
2. **#93 试点反馈**：出现明确的、L0/L1 结构上不可能的瓶颈（手写扫描页识读、
   语义近似归一），且有可计量的时间损失。
3. **#92 出境授权落地**（无论结论是允许还是禁止——"禁止"同样解锁 §1.3 那条唯一路线）。
4. **§2 与 #122 的 compose 决策已完成一次**：那时 L2 的部署代价才有具体数字可估，
   而不是"估计很贵"。

反过来说：**在这四条之前开 L2 实现 issue，等于在没有尺子的情况下改机器。**
