# 界面契约

产品取舍见[初心与长期方向](PRODUCT_POSITIONING.md#6-初心如何影响产品取舍)。界面首先帮助人完成当前任务：找回材料语境、保留地方差异、理解下一步与成果去向。长期愿景不增加无实际作用的入口或让用户承担额外填表。

## 项目连续操作（2026-11-12）

项目概览以紧凑统计、建议下一步和四步分工清单组织。待办队列读取仲裁、拼音归一、来源复核与未处理成员事项四类数量；尚未读取时显示“未读取”，不能用零替代。来源与列表共用待复核谓词，成员按有报告且未处理完成的事项计数，不按报告份数；默认待办入口筛选未处理，全部历史仍可切换。全项目仲裁入口清除旧搜索、质量、页码范围和列表页码；普通条目入口保留原筛选。项目访问失效时清空待办数量与入口。

CSV 预检完成后先明确显示「检查完成，待确认」及尚未写入条目的说明，再呈现来源、数量、错误与人工确认。编码、表头和作业信息在过程详情中查看，跳过提示在主区可见。前20条只读样本默认折叠。帮助按角色组织，从项目进入后返回同一项目及导入方式。

项目待办在各自事项旁呈现读取中、失败、上次读取值与重试。交付记录沿用同一套加载和错误提示。下载动作有独立的准备反馈，浏览器接手文件后提示由接收方核对，再登记回执。

编选与交付详情保留返回列表页码。创建成功后直接进入已保存详情；同一交付记录重复打开回执时保留当前输入并定位登记区。回执按事件、说明与核查者、关联凭据分组；只有多页历史才显示分页，重发信息按需展开。下载不改变回执状态。

本轮沿用现有令牌和组件；本地验证与真人验收边界见[操作体验验收](evidence/usability-20261112/README.md)，后续计划见[以真实使用体验为主的优化方案](plans/2026-11-12-human-usability.md)。

本文件记录已经落在 `frontend/src` 的行为。源码指针使用文件路径与选择器/导出名，避免格式化后行号漂移；本轮尚未完成的真人、原生设备及读屏验收见 `docs/evidence/workbench-experience-20261107/human-acceptance.md`。

## 基调与令牌

产品名为「万语校坊」。纸色底、墨色字、朱砂点缀来自 `style.css` 的 `:root`：`--paper`、`--ink`、`--accent`。颜色、圆角、层级、字体栈只在令牌定义处写字面值，调用点使用变量，不重新定义一套配色。

`--space-1` 至 `--space-6`、`--text-xs` 至 `--text-2xl`、`--radius-*`、`--z-*`、`--badge-*` 与状态色也定义在同一 `:root`。新组件使用这些刻度；常规界面15px、次级文字13.5px、辅助标注12px，校对输入18px。`--control-height` / `--control-height-sm` / `--control-height-touch` 分别为40/34/44px，手机主要触控目标至少44px。

工作台与任务／项目目录使用同一 `--page-width`（1200px）和28px常规页标题。沉浸作业区与需要宽表格的项目工作区保留各自布局。原生按钮、按钮样式链接及公共按钮共用40/34px高度刻度，手机主要操作保持44px；链接继续使用真实链接语义。

字体约定：

- `--font-rare` 同时包含 `Fangji Phonetic` 与 `Fangji Rare Han`，不能遗漏任一家族。
- 普通界面与常规页标题使用 `--font-ui`，系统无衬线字体优先；音标字体不能放在 UI 字体栈首位，以免普通英文和数字混入记音字体。品牌和少量编辑性标题使用 `--font-display`，码位说明使用 `--font-mono`。
- 字段值、`.proofread-textarea.form-control`、`.final-value textarea`、`.ipa-key` 优先使用 `var(--font-rare), var(--font-ui)`；记音与缺字先由随附字体呈现，普通字符仍有系统回退。
- `AppFieldValue` 统一承载 `white-space: pre-wrap` 与 `overflow-wrap: anywhere`。调用方只负责间距、字号和布局，不再自行复制文本保真规则。
- 已明确的 IPA 字段使用 `lang="und-fonipa"`。未知方言转写不猜成英语或其他语言；来源明确时可显式传入语言。

字体覆盖集合由 `lib/fontCoverage.json` 给出，测试与原始字体 manifest/Unicode 范围精确比较。`useFontAvailability` 区分加载、失败与重试，并丢弃旧请求。含受保护字符时，加载完成前必须有提示；失败时保留原字符串与码位提示，不能用形近字替换。多个字段可以共用 `RareCharacterNotice`，并关闭子项重复提示。

UI 债务的实际判定由 `scripts/check_ui_debt.py` 与 `scripts/ui_debt_baseline.json` 执行。所有类别都为 fail 棘轮：静态内联样式为0，保留6处运行时进度/尺寸绑定；原生表格只有 `AppDataTable` 内1处；颜色、圆角、层级、缺角色提示、自制模态框、未定义变量和字体栈字面值债务均为0。上限只能下降。

## 领域编排与大视图

`ProjectDetailView` 与 `ProofreadEditorView` 都小于300行，只负责获取、编排和布局，不新增全局业务 store。

项目空间由 `lib/projectWorkspace.js` 映射为概览、材料、校勘、交付、设置五区。条目默认打开；初次成功统计确认为空项目时转入材料，不把读取失败误认为零条。PDF/CSV/Review Bundle/OCR、台账、导出、机器检查、归一等模块按需分包，首访才挂载，已打开面板在同项目切分区时保留，避免丢失预检、上传和未保存内容。跨模块刷新仍使用明确回调与事件，不新增全局业务 store。

设置按基本资料、校勘规则、成员与账号、输入工具、所有权分区读取和保存；无关资源失败不阻断基本资料。来源核验默认进入问题队列，核验约定可在设置中维护。问题列表与单事项详情分开，批量合并/拆分仍保留明确依据。编选和交付分别为列表、创建/准备、单批/单包详情，归一把转换作业与单条人工复核分开。

编选页将历史、汇总、创建、批次详情和单条例外拆为领域面板；交付页将记录列表与回执编辑拆开。父页面统一持有请求、权限失效、路由和未保存状态，子面板通过具名模型与事件交回用户输入。回执面板提供明确的焦点入口，打开或重复打开时均聚焦标题，保留已输入内容。样式使用各自工作区的类名约束，确认弹窗中的内容沿用相同样式。

作业页使用 `DocumentReviewWorkspace.experience-workspace`。桌面默认45/55双栏，分隔条支持指针和方向键调整（30–65%）。原文工具栏优先呈现显示范围、页码和常用缩放；「显示选项」提供旋转、全屏、缩放滑块和预览说明，Esc 收起后焦点回到触发器。换页请求标出目标物理页。来源/约定默认摘要，阻塞、未完成或依据失配时自动展开。校对字段的编辑值与导入文本分别呈现，修改后才出现恢复操作。仲裁默认差异字段，来源复核和无差异情况展示全部字段，采用值不自动改变来源正误。

字符托盘默认关闭，开合与分栏按用户/项目存本机偏好；最近字符按精确值保留，搜索支持字符、提示和码位。不因搜索、缩放、托盘切换改变原字符串或光标选区。校对、租约、草稿、提交、退回及本人只读回看继续由原有 composables 和服务端裁决。

字符查找兼容规范等价的写法，例如输入 `ã` 或 `a＋组合鼻化符` 都能找到键盘中的 `ã`。这种等价匹配只用于查找；显示、插入、最近字符和码位搜索保留键盘定义的原值，不合并原本不同的键，也不把兼容字符替换成普通字母。

## 本条原文与整页上下文

`DocumentReviewWorkspace` 的原文工具栏在存在可信定位时显示“本条局部 / 整页”，默认显示局部。同页连续切条也更新位置；查看邻页暂用整页，回到本条页恢复当前选择。无定位的历史记录和 CSV 仍按原有整页方式查看，不出现失效的局部按钮。

`useProjectPdf` 分开处理可复用的页图字节和每次授权返回的条目位置，校对者不能看到上一条的局部框。显示前核对条目、物理页、实际预览标识；页图与 PDF 回退均使用该规则。新条有定位时回到自己的原文页；同条续签不重置阅读位置；无定位的连续任务保留既有整页阅读习惯。

`PdfSinglePageViewer` 保留字形外的上下文留白，局部自动适配最多为整页适配倍率的三倍，手动缩放继续可用。手动旋转进入整页，重新选择本条局部恢复来源页面方向。局部仍显示身份水印。手机沿用原文展开入口，切换范围不自动抢走编辑焦点。

用键盘翻页或从邻页返回“本条局部”时，加载期间焦点停留在原文区。加载完成后回到原控件，若到达边界则回到页码输入框。用户已切到编辑区时，焦点留在当前字段。

读取或显示原文失败时，就在错误提示旁提供“重新读取原文”，正常工具栏不增加常驻按钮。重读重新获取已授权的原文，避免反复使用损坏的预览；同一来源保留阅读页和局部/整页选择，不重置字段、草稿或核验状态。重读按钮消失时焦点留在原文区域，手机仍可收起原文继续填写；没有来源或没有权限时保留实际提示，不承诺重读能补齐材料。

允许重读的非全屏显示错误态收起阅读工具栏，让窄屏先看到错误和处理入口；恢复后工具栏重新显示，全屏时保留退出。已知 PDF 解析、密码保护、文件缺失错误使用中文说明，不要求用户理解解析器的英文报错。

定位只改变查看范围，不修改原文、录入值或来源判断。产品使用有含义的操作名称，不展示内部阶段字母。范围、材料与实际核查记录见 [逐条原文定位方案](plans/2026-11-12-source-preview.md)。

## Reka UI 精修样板

依赖锁定 Reka UI 2.11.0，公共外观集中在 `styles/ui-components.css`，不在业务页面直接散布组件库样式补丁。首批仅精修工作台、项目条目列表与桌面/手机校对，公共字体和控件令牌作为共享基础。其他旅程继续按此规范逐步迁移，不把首批验收等同全站验收。

工作台只有一个当前工作主入口，优先恢复仍可访问的工作；无当前工作时提升待仲裁或可领取工作。项目进展收为去重列表，读取失败仍显示错误与重试。项目条目默认关闭批量选择与高级筛选，URL已有筛选时展开对应筛选；普通待校对与质量待定分别以中性文字呈现，仲裁/异常继续突出。手机列表在同一表格内容列呈现进度与质量摘要，避免重复交互与整页横向滚动。

工作台当前事项使用紧凑横向组合，项目、事项与唯一主操作相邻，手机自然上下排列。`AppButton` 的可选 `loading-label` 预留正常与忙碌文案的自然尺寸；不提供时 spinner 不增加按钮宽度。正常内容不能由调用方在 loading 时改成长文案再期待尺寸保持，刷新／领取等样板使用固定 slot 和 `loading-label`。按钮继续保留可访问名称、原生 disabled、属性/事件透传与 focus 方法。

条目列表按 `ocr_row_json` / `row_headers_json` 与已有列用途接口组织词目、记音、释义和备注；显式用途优先。用途暂不可用时显示原列名与重试，不猜测语义。无结构记录直接显示完整 `ocr_text`，不按空格拆词。原始字段、合法空白和完整导入文本可展开查看；展示分组不修改原值、搜索或导出。项目管理在手机用同一份表格行排成摘要，项目、待仲裁和主操作无需横滚；状态与创建信息按需展开，桌面保持语义表格。

条目原值与字符说明使用 `AppDisclosure lazy`，首次打开才创建内容，之后关闭/重开保留同一DOM。容器与ARIA关联始终存在，来源阻塞区保持默认即时挂载；默认打开和受控展开也立即呈现内容。列表复用当前账号/项目的列角色对象，每条不再反复序列化/解析同一角色；字段和原值仍独立按保存顺序读取。聚合字体输入使用稳定computed，相同字符集不重复检测或闪回加载态；新增字符与显式重试继续检查，迟到响应仍被隔离。

字体范围仅在初始化时合并相邻区间，不改字库、字体优先级、覆盖或Unicode值；全码点分类与原始manifest核对。校对输入立即更新模型及change/草稿事件，普通输入在DOM更新后自动增高一次；IME组合输入尚未提交模型时仍按其可见文字增高，不等到组合结束才响应。性能量测与边界见[性能验收](evidence/ui-performance-20261108/README.md)。

仲裁按差异字段组织紧凑候选行，最终值为主要编辑区，各份结果和最终值的来源判断在独立区域维护。采用结果不能自动设置来源正误；未决门槛与原确认框保持。来源变化、规则不兼容和来源未批准分别显示并自动展开；手机保留紧凑原文/队列头和底部总览入口，桌面主检查入口位于顶部。依据、批量工具及历史共用 `AppDisclosure` 的短时过渡，不延迟路由/身份/权限失效时的卸载。

第二轮把我的任务、我的项目、可加入与项目管理四个目录扩展到同一视觉基准：去除重复眉题、装饰色边与统计卡片，统计改为带单位的紧凑定义列表，刷新／领取／加入共用 `AppButton`，管理次要动作共用 `AppDropdown`。任务与项目的URL、项目级能力、筛选分页、加入与领取行为保持。目录刷新失败保留旧结果及明确重试；没有读到统计时显示未知，项目数与材料条数不拼成比例。

校对结果位于字段主体，导入文本作为紧凑对照；短字段可双列，多行字段自然跨列。textarea 按内容增高但保留可滚动上限，换行、空白、组合字符与选区不得被修整。手机原文入口在任务头，默认专注当前字段，字符搜索与分类压为一行。健康来源摘要紧凑呈现，失配/阻塞仍自动展开。

手机字段底栏保持单行：选择字段、持续可达的总览／提交入口和有可见文字的下一字段操作。最后一字段以总览入口作为主动作；总览明确区分返回编辑与检查提交，仍通过原确认框及服务端门槛。本人回看使用总览／返回查看／查看此字段，不提供提交；仲裁与来源核验保留各自判断名称及未决禁用规则。进入总览不标记字段已核对，也不产生提交，textarea继续使用原DOM以保留字符与选区。

校对任务头始终保留一行真实状态，普通编辑、本机草稿、提交中、服务端已提交、失败、离线与租约失效不再靠增删大提示块切换。服务端已确认后即显示已提交，后续领取下一条单独表达进度，不能在领取返回前宣称空队列。本机保存失败不称已保存；浏览器离线信号只作检测提示，不证明提交结果、不阻止人工核对重试，也不自动重发。完整服务端错误、租约重领与下一条重领入口留在相关工作区，成功详情按需展开。

状态行持续提供可触控的“详情”，用既有 `AppModal` 展示完整草稿时间或状态依据，不依赖悬停；打开详情不提交、不替换输入节点，关闭后焦点返回触发器。条目或回看身份变化时关闭旧详情。说明、状态及恢复弹框打开时，编辑器提交/保存/邻居快捷键不能穿透；只有原提交确认层继续支持其提交快捷键。

快捷键提示只呈现当前可用操作：单条进行中任务不提示方向切换，本人只读回看不提示保存或提交，回看邻居只展示实际可用的方向。方向键不创建第二个活跃任务，提交仍先打开核对确认。

动效统一使用 `--motion-fast` 120ms、`--motion-normal` 180ms、`--motion-slow` 220ms 与 `--ease-out`。按钮过渡颜色和边框；原文显示选项、窄屏展开原文及字符托盘使用短时入场过渡。手机的「下一字段」立即聚焦新的字段区域，继续保留输入节点及选区。保存反馈按真实结果即时更新，上一条的操作结果可在新条目的状态行读取。减少动态效果设置关闭位移和入场动画。路由、任务、账号和权限变化即时生效。

目录导航与行悬停、输入边框、字符按键及进度条沿用上述时长。账户菜单与状态文字仅作即时入场反馈，关闭与业务状态更新不等待退场动画；减少动态效果时取消菜单／文字入场及按键缩放。异常恢复区没有自动消失计时器。

Reka 提供的运行时定位变量在 UI 债务检查中逐个登记；近似拼写仍报错。回归入口 `run_frontend_quality_browser.py --only components` 验证空值/数值选择、禁用/忙碌、键盘菜单、菜单到模态的焦点交接、窄屏弹层及减少动态效果；`workbench` 组包含真实临时后端的条目样板检查。

新手提示为三个可跳过、可重放的非模态小贴士，入口放在应用页眉，不占字段与底部导航区域，也不阻断编辑器快捷键。研究用途告知和提交前明确选择保持独立，不将查看/跳过提示当作同意。

纯拆分阶段的项目详情正常/空与禁用/错误三种状态，与原版整页 PNG 字节及管理请求顺序完全相同，见 `docs/evidence/backlog-20261106/`。最终界面另含本轮共享组件、字体、移动端和 OCR 的明确行为改动，不把阶段对照冒充最终界面零差异。

## 四态与读取生命周期

应用启动时先显示登录状态更新提示，再进入路由页面。登录刷新在10秒内未完成或遇到临时错误时，显示明确失败与重新尝试入口，保留当前登录信息；服务端明确拒绝凭据时清除失效会话并进入登录流程。超时、重试或离开页面后的迟到响应不能恢复旧会话或重复挂载应用。

页面进入浏览器往返缓存时只暂停启动：取消未完成刷新并隔离迟到响应；缓存恢复后以新一代刷新继续启动。已经挂载的应用不重复挂载，恢复后的网络失败仍可手动重试。真正离开且不进入缓存时才永久销毁启动控制器。

| 状态 | 语义 | 必须保留 |
| --- | --- | --- |
| pending | 请求未完成；骨架装饰节点 aria-hidden | 明确加载提示；已有成功结果可继续查看 |
| empty / none | 成功返回但没有记录或匹配 | 当前条件与清除/恢复入口 |
| empty / not_computed | 尚未运行计算 | 不能说成没有问题 |
| empty / not_authorized | 当前无查看权限 | 不能说成没有记录 |
| error | 本次读取失败 | role=alert、重试、已有成功值和用户输入 |
| danger | 不可逆或需认真确认的操作 | 明确文字、可见焦点、确认入口 |

成功/进行中的动态反馈使用 role=status；错误使用 role=alert；静态说明使用 role=note。状态不得只靠颜色表达。加载错误与操作错误分开：保存/校验失败显示在原编辑区，不得把输入和按钮一起隐藏。统计没取到时显示未知，不伪装成零。

读取资源的取消和代际保护由公共 helper 实现。查询切换、项目切换、卸载与迟到响应均不得复写当前数据。分页失败保留最后成功页与详情，重试针对原失败目标；成员候选游标同时绑定项目、操作者与查找词。

## OCR 界面边界

正式链只接收不含图像且可映射的单栏纯文字层页面。扫描引擎的离线实测发现难字静默替换，默认拒绝扫描，backend也独立拒绝实验worker的扫描输出发布。失败保留原 PDF，提示改用人工转录或CSV，不把错误猜测变成正式条目。

当前单栏输出不推断领域分列。原字符串、空格、坐标与识别时「确定/待确认/弃权」分别保留；确定不表示来源核验正确。管理修正不改原始识别记录。单作业最多200个物理页，超出明确要求分段。原始JSON通过管理权限接口下载，认证token不写入链接。

识别作业显示固定的物理页段；进行中只依据已保存进度列出首个未完成页，不把它称为正在识别页。页级失败消息使用后端实际页号定位，失败批次仍不发布暂存条目。含图像页的提前拒绝与单作业内连接复用只改善处理效率，不改变扫描拒绝、原始证据或人工核验门槛。

## 身份与离开页面的状态隔离

`App` 按当前账号重建受保护页面；退出和强制改密状态变化会重新执行既有路由门禁。公开登录页保留自己的原目标跳转，不因身份发布而提前销毁登录表单。项目管理子视图通过 `lib/adminRouteKey.js` 按路由名、项目和仲裁条目重建，查询条件变化仍保留当前工作区。

异步登录、外部绑定、身份刷新与资料保存只可向发出请求时的当前会话发布凭据；会话期间被退出或替换时，迟到结果不能恢复旧账号。账号变更也会清空权限上下文与共享请求，权限入口仍由既有服务端裁决。

同组件切换校对条目时，在清除保存计时器、替换页面引用之前立即落盘最后输入。来源或约定失配的本机旧草稿先归档再清除当前键；重读上下文不再次重置已经开始的新输入。核验面板的读取、排队草稿和问题提交均绑定任务代际，卸载使旧代际失效。归一复核只接受最后一次查询响应，刷新同条目保留人工填写，PDF 回退预览也按授权到期时间重新读取描述信息。

问题处理表单按事项保留已读取的基线。重新读取时，未修改表单同步最新记录；未保存草稿只在服务器版本不变时继续编辑。服务器版本变化时保留草稿并明确提示冲突，阻止保存，须先自行保留需要的文字、采用最新记录后重新编辑。保存成功按返回记录更新基线，保存期间追加的输入继续保留为未保存草稿。问题与来源复核的空列表均使用 `reason=none`，筛选为空时仍可切换范围。

### 归一草稿的依据变化

归一复核草稿按条目和完整复核依据共同绑定，同依据才保留可编辑内容。依据变化时只读归档旧写法/旧依据，当前表单清空并锁定；明确开始重新填写后才允许输入新结论。409后若新队列未成功加载，不能把旧来源重新标为当前依据。离页、筛选或已移出队列的工作区草稿有只读查看入口；关闭工作区前需自行保留，不冒充服务端已保存。API兼容与事务约束见 `docs/scheme-normalization-review.md`。

## 后台作业、账户与可恢复管理页

作业观察按`authEpoch:userId:projectId:kind:jobId`共享GET与快照；账号/项目/作业变化取消旧请求并丢弃迟到结果。同用户正常token刷新不换代。活动面板2秒、隐藏面板/文档15秒；失败2/4/8/15秒退避，离线暂停、恢复立即读。GET10秒未完成视为连接陈旧，不能宣告服务端作业失败。最后订阅者离开清理计时器。CSV validated为待确认；转换total_count为已处理量、无完整分母，不显示假百分比或ETA。

CSV预检展示前20条有效行的只读样本；`preview_locations`与原preview同索引，单独表达CSV行号和PDF物理页码，不占用用户列名。入口“提取PDF文字层”只承诺当前正式支持能力；练习CSV与正式项目明确区分，不声称它完成ReviewBundle交付。

管理员帮助另提供完整虚构Review Bundle、配套3页PDF和可重放说明，贯通独立校对、来源/许可判断、单批次编选与交付检查；预检不替人确认，不自动登记或授权，外部回执仍须真实接收后填写。

编选列表、创建及详情以query表达`page/view/batch/tab/exception`，交付以`page/view/adoption/package/tab`定位。详情按ID读取，不能从当前列表页推断；会卸载未保存编辑对象的query变化须确认。权限失效不受离页确认阻挡。账户安全归入账户与偏好，不高亮项目。

原生交付仅接受规则显式指定的单个完整入站Bundle。先验证全项目scope_digest，再按目标入站批次构造完整声明；界面分别展示编选项目范围与本包范围。preflight绑定全部正文/来源/前包的preview_sha256，生成按request_id幂等；同key异体409、成功响应丢失可返回同一包并标replayed。交付链为project/recipient/purpose/import_job。旧包字节和历史previous不改写；待定或范围外只交付标识与理由。人工填核查者不是额外身份认证。

页面性能观测只记录固定业务时点及脱敏时间；原文以实际image load或canvas render完成后的绘制帧记source_visible，不用API结束代替。不会上传恢复链接token、URL/query/hash、输入值或DOM选择器。


### 主动退出与运行证据

AppShell 的显式退出先经账户隔离的 draft registry 同步保存编辑器待写入值，再检查当前用户本机草稿；保存失败可返回处理，有草稿可返回、前往本机资料或明确保留后退出。确认绑定当前认证代次，A→B→A不能沿用旧确认。强制401失效、外部撤销和auth-store清除路径不受确认框拦截。不引入通用全局logout拦截。PDF旧worker异步销毁后再次核对请求代次，过期加载不能新建worker或覆盖新任务。

PDF 预览由 `useProjectPdf` 先从受保护接口取得已授权的 blob；Viewer 在创建 worker 前可取消地读取该本地 blob，经代次检查后把原字节交给 PDF.js 的公开 `data` 接口。这样退出、切账号或换来源不会在 PDF.js 3.11 的 URL 传输仍等待头信息时终止 worker，触发其终止后的错误回调。读取和解析的真实错误仍显示；取消及过期响应不能发布旧文档。不增加外部请求、不修改 PDF 字节，读取期间暂有 ArrayBuffer，再转移给 worker；本修复未作额外容量承诺。

部署采集器默认60秒采进程/数据库/WAL/磁盘，缓存目录默认300秒只扫元信息；--backup-receipt指向完整备份原子发布的本地receipt.json，--backup-max-age默认24小时。未配置、过期或损坏均明确显示，不等于异地加密、通知或恢复通过。run_restore_business.py沿既有suite验证恢复后原账户、项目、附件、领取、提交、仲裁与导出；本地小型演练结果不能代签生产RTO。

### 用户可见的流程名称

界面、帮助、校验提示和历史事件显示有含义的步骤名：资料导入、独立校对、来源核验、拼音归一、批次编选、交付与回执。内部流程代号只留在实现和交换协议中，展示时映射成名称；例如退回位置显示“来源与权利”或“批次编选”。难度筛选使用“基础核对、需要判断、需要专业知识”。不把内部字母直接当标题、标签、导航、错误或历史说明，也不因此修改资料中的真实拉丁字符、音标及既有机器枚举。

难度领取落空和管理员登记、撤销结论后的回显也复用同一套名称。判断依据展示为“缺少 PDF 原文页码”等可读说明，不直接显示内部规则标识或数组；未知规则显示“其他判断依据”。已评估但线索不足与尚未评估分开呈现，难度及依据仍来自服务端实际结果，不由中文标签重新推断。

### 练习身份与任务续接（2026-11-12）

练习身份由项目记录确认；材料来源上下文不能充当练习绑定。角色、步骤、项目均使用限定范围的路由参数，当前账号与项目用途核对后才提供业务深链。创建后回当前步骤，项目工作区与来源库可返回练习。练习清单展示当前查看位置与真实记录，不用自记勾选表达完成；练习标识在项目入口可见，转入正式工作时另选项目。

### 材料准备与原文定位（2026-11-12）

CSV 导入依次呈现选文件、选择 PDF 物理页码列、检查与确认。所选列旁显示少量原值，默认候选明确可更改；更改列选择先撤下旧确认，再重新预检。预检样本的定位列与内容列分开展示，不把所选页码重复显示成空内容字段。后端保存有效映射，旧自动识别与等价显式选择使用同一作业身份。

### 材料准备续接（2026-11-12）

项目页再次打开时，应能辨认当前主 PDF，并直接预览原文、逐页查看，再从同一项目继续 CSV 导入或 PDF 文字提取。老文件可能没有保存页数；此时不把空值说成零页，预览应读取实际 PDF 页数并明确它是本次读取结果。替换 PDF 在新文件上传并通过校验前不得遮住当前主文件；失败时保留旧主文件和依赖它的原文关联，并提供可理解的恢复操作。未完成上传应说明如何重新选择同一文件继续或何时需要重新上传，不能暗示刷新后本机文件仍在。

Review Bundle 先检查包格式，再核对包声明的来源登记标识。缺少登记时不得确认导入：提供复制标识、在新窗口打开登记页及回到原页重新检查。登记页须明确只有平台管理员可新增来源；项目管理员可发起处理但不因此获得登记权限。新窗口方案依赖原项目页仍打开，所选 ZIP 保留在原页；离开或刷新后须重新选择并检查。来源已登记只说明登记记录存在，不代表该用途获准，许可结论仍须单独核对。正常提示使用“主 PDF”“资料来源”等含义明确的中文名称，不向使用者暴露内部步骤代号。

这一续接属于 21 天方案中的材料准备减负：降低返回项目、核对原文、恢复导入和处理来源缺项的操作成本。它只为来源可追溯、材料可核验提供基础，不代表系统已完成多模态在地文化知识生成，也不证明资料具有使用许可。该独立切片以 PR #435 的 `10222bb` 为基线，在 `feat/material-continuation-20261112` 开发；当前代码走查不能替代真实管理员与项目成员的独立体验验收。

## 批次报告与连续处理（2026-11-12）

批次台账首列提供报告入口，状态显示中文。报告首屏说明当前批次、统计时刻及可继续的操作；进入条目与仲裁后保留批次范围，并在列表明确显示范围及返回报告入口。项目总数与当前筛选数量分开呈现。

## 统一待办与处理回程（2026-11-12）

管理员从工作台或项目管理打开统一待办。页面按“项目 × 工序”列出当前工作，项目与阶段筛选保存到 URL。行内相邻呈现项目、工序、带单位数量、负责角色、最早等待时间和实际处理入口，复用纸色、墨色、青色令牌与 AppSelect、AppStatusPanel、AppPagination。手机同一行内容自然分区排布，不另造重复统计卡。

处理入口优先定位具体仲裁条目、来源事项、编选批次或交付包。归一与来源核验进入当前队列。返回上下文在原项目和业务流程内随详情切换和刷新保留。统一待办读取完成后恢复原筛选、位置与操作焦点，已处理的行消失时聚焦结果标题。仲裁的差异进度位于字段滚动区外。选中的候选值有即时文字及按下状态，短时高亮遵循减少动态效果设置。

服务器汇总每种工序的当前业务状态；读取失败显示未更新，缺失开始时间显示未记录。编选单位是批次，交付单位是包，不混为个人绩效分数。失效项目筛选允许清除后继续查看其他有权项目，无效阶段不得无声扩大范围。

退回与回执分开表达：交付包的当前处置状态从完整事件记录推导，与统一待办共用口径。已退回或撤回的包不继续显示等待回执；登记处置不会伪装成接收成功，历史回执仍保留。

来源复核将可核验或仲裁与等待校对分开；待办只统计前者，后者仍可从来源页面查看、确认空记录和继续项目条目。拼音归一把可用规则与已有工作分开呈现：规则缺失不隐藏复核队列与草稿，按条目说明当前阻塞原因；只有满足实际规则条件时才提供确认操作，技术配置详情按需展开。
